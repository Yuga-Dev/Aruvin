# Aurvin: prompt caching and compaction fixes

Preserve Aurvin’s fast, low-cost normal path. Keep assembling prompts from fresh server-side metadata and existing history; don’t persist system metadata per turn, add routine model calls, or introduce storage I/O before model dispatch. Research and unified code review are skipped. Planning, regression tests, and final verification are not.

## Scope and acceptance

1. **Make Stage 1 useful on actual overflow.** In Web-only and composite Calendar/Web prompts, try a bounded in-memory projection of stale historical Web results before waiting for LLM compaction or rejecting for context overflow. Use real turn boundaries after native insertion, preserve the active/recent turns and evidence needed for pending work, keep exact source URLs and native call/result pairing, and minimize how early the prompt changes. Finalize the provider request after folding; run the normal admission checks on the exact dispatched messages. Non-foldable overflow still follows the bounded fallback. Ordinary admitted turns never fold, and canonical history and provenance remain untouched. At checkpoints, pass useful, validated folded Web evidence for the selected completed turns instead of counting it solely for scheduling. Don’t enable lossy Calendar, title-based Canvas, or catch-all plugin folding.
2. **Keep Canvas state out of the reusable history prefix.** Render fresh voice-only state near the current turn, including tool continuations. Keep stable assets ahead of personalization, date, and mode where compatible with the existing prompt semantics; retain the catalog’s placement before compacted history. Preserve Canvas ownership checks, exact current input, tool grouping, and all existing limits. Assert that changing only Canvas state leaves older wire messages unchanged. Preserve current provider caching defaults unless a supported static breakpoint can be added without broadening cache writes or changing eligible routes; record anything that needs live evidence rather than claiming savings or blindly enabling hints.
3. **Align provider routing and same-model compaction.** Use one server-derived conversation routing ID across plain, Calendar/composite, Web-only and same-model compaction requests. Feed same-model compaction the exact safe stable prefix shared with the live serializer when available; do not replay volatile Canvas state, attach live tools to the summarizer just for caching, or carry private/stale Calendar data into a new snapshot. Keep custom-mode compaction bounded and lean. Ensure overflow rebase settles with the valid active-turn handle; preserve concurrent turns and cancellation.

## Simplicity and verification

Always rewriting history is rejected because it loses cache reuse on ordinary turns. Fixing only Web’s cutoff is rejected because the captured wire request and composite path would stay broken. Use targeted fixes at existing assembly and transport boundaries; no new dependencies, storage schema, provider lock-in, or admin settings.

Use deterministic tests to verify the serialized requests, successful overflow rescue with no additional model request or storage I/O, stable ordinary prefixes, budget rejection when protected content alone is too large, valid compaction rebase/finalization, and preserved Calendar authority and Canvas behavior. Run the backend build, lint, and tests. Use existing usage/timing evidence to identify what to measure after rollout (cost, cache reads/writes, and first text/audio); do not run paid or live provider calls or claim measured improvements without evidence.
